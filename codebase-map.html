Sensory profile

A user’s sensory eating profile: texture preferences, temperature, dietary needs, cultural requirements, and per-food classifications (SAFE / UNSURE / UNSAFE). Profiles are accessible by a hashed 3-character code with brute-force lockout.

  • FEfrontend/src/views/SensorySetupView.vueMulti-step setup form
  • FEfrontend/src/views/SensorySummaryCompactView.vueCompact summary screen

Frontend — components

  • FEfrontend/src/components/sensory/FoodItemRow.vuePer-food row (status, notes)

Frontend — composables / state

  • FEfrontend/src/composables/useSensoryProfile.tsReactive profile, fetch/save
  • FEfrontend/src/composables/useSensorySetupForm.tsSetup wizard form state

Frontend — lib / types

  • FEfrontend/src/lib/persistMinimalSensoryProfile.tsMinimal-payload save helper

  • BEbackend/src/routes/sensory.ts/api/sensory/* endpoints, code hashing & lockout

Auth & session

Lightweight identity model: a per-browser biteBudUserId sent as the X-User-Id header. Sign-in screen and a “new user” onboarding view; no passwords.

How to use this map. For any feature you’re developing, start at the matching section. Touch the view first to see the user-facing screen, follow imports into composables + lib for client logic, then hop to the matching backend route file and from there into services and the Prisma schema. Database changes always need a new Prisma migration.
